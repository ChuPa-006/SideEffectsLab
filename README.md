# SideEffectsLab — Practice 9

A small Android Studio project for the six hands-on tasks in **Practice 9 — Side-effects**. It uses Kotlin and Jetpack Compose. Each practice task is available as a separate screen from the home menu.

## Open and run

1. Extract the ZIP file.
2. Open the `SideEffectsLab` folder in Android Studio (`File → Open`).
3. Allow Gradle sync and install any Android SDK platform that Android Studio requests. The project uses `compileSdk = 35` and Java 17.
4. Run the `app` configuration on an emulator or Android phone.
5. Open **View → Tool Windows → Logcat**. Select the running app and search by the tags listed below.

The included lightweight Gradle bootstrap launcher downloads Gradle 8.9 from the URL in `gradle/wrapper/gradle-wrapper.properties` on first use if it is not already cached. Internet access is needed for that first launch and for Gradle dependency resolution. For a production repository, prefer the official Gradle wrapper generated by Gradle itself.

## What each task demonstrates

| Task | Implementation | Why this API is used |
|---|---|---|
| 1. Splash screen | `Task1SplashScreen.kt` | `LaunchedEffect` waits for two seconds. `rememberUpdatedState` calls the latest callback without restarting the timer. A third variant uses the callback as a key to demonstrate repeated cancellation/restarts. |
| 2. Snackbar button | `Task2SnackbarScreen.kt` | `rememberCoroutineScope` starts `showSnackbar` from the button callback. Leaving the screen cancels the screen-bound scope. The second tap can queue another snackbar while the first is active. |
| 3. Lifecycle logger | `Task3LifecycleScreen.kt` | `DisposableEffect(lifecycleOwner)` registers a `LifecycleEventObserver`; `onDispose` removes it. The switch shows/hides the observer composable. |
| 4. Analytics | `Task4SideEffectScreen.kt`, `LabModels.kt` | `SideEffect` copies the current `userType` to an external `Analytics` object after every successful recomposition. An unrelated counter forces recomposition without changing `userType`. |
| 5. Scroll | `Task5ScrollScreen.kt` | The two 100-item lists compare direct index reads with `derivedStateOf`. `snapshotFlow` plus `map`, `distinctUntilChanged`, `filter`, and `collect` sends one event each time the derived list crosses from index 0 to an index greater than 0. |
| 6. produceState (bonus) | `Task6ProduceStateScreen.kt`, `LabModels.kt` | `produceState` converts the fake suspend repository result into Compose State with Loading, Success, and Error. The repeated identical assignment is logged for the no-extra-recomposition check. |

## How to check the tasks

### Task 1
Open Task 1 and wait more than two seconds. The direct-capture variant should log an older callback version (normally `v0` on the first run); the updated-state variant should log the latest version. The extra variant shows that `LaunchedEffect(onTimeout)` restarts whenever the callback changes. The “Restart all comparisons” button allows another run.

### Task 2
Tap **Show snackbar** once or twice. Tap **Navigate to Lifecycle screen while snackbar is visible**, then use Back to return. The screen's `rememberCoroutineScope` is cancelled when the screen leaves the Composition. Compare the `showSnackbar coroutine started/finished` lines.

### Task 3
Toggle **Observer visible** on and off several times. Every `addObserver` line should have a matching `removeObserver (onDispose)` line. Use the app background/foreground to see `ON_STOP` and `ON_START` lifecycle events while the observer is registered.

### Task 4
Select `free`, `premium`, or `admin`. Then use **Force recomposition without changing userType**. The `Task4SideEffect` counter should increase even when `userType` itself did not change. Press **Read Analytics.userType** to read the external value after the effect has run.

### Task 5
Scroll each list slowly and compare the two composition counters. The direct-read version is expected to recompose more often. The analytics event is collected from the derived list; it should send one event on each transition to an index greater than 0, not on every item change.

The recomposition counters use a small Android `TextView` updated by `SideEffect` rather than Compose State, so the counter itself does not create an infinite recomposition loop.

### Task 6
A URL ending in `.png` returns Success; other URLs return Error. Change the URL while loading to cancel/restart the producer and show Loading again. The fake producer intentionally waits with `awaitCancellation()` after loading so leaving the screen or changing the key visibly runs its `finally` block. This extra wait is for the lab's cancellation experiment; remove it for a normal one-shot image load.
